# Macro OS AI Company Recovery & Continuous Improvement Plan

## Objective

Convert the expert audit into enforceable controls. Macro OS remains a
macroeconomic and investment-intelligence research system; this plan does not
expand Product Goal scope.

## Required chain

`Product Goal → user job → hypothesis → bounded change → independent review → runtime/data evidence → measured outcome → conservative scorecard delta`.

Missing evidence means `HOLD`, `REVISE`, `ROLLBACK` or `KILL`, never automatic
success. A green build is not production readiness.

## Recovery waves

1. **Governance reset:** enforce scope-policy, park out-of-scope backlog,
   reconcile state/ledger/scorecards, require five-epoch process reviews and
   confidence caps.
2. **Trust reset:** remove hard-coded claims/status/value; expose
   cataloged/implemented/local/production/released and unavailable/stale/partial
   states.
3. **Core workflow:** optimize `Discover → Inspect evidence → Compare → Save →
   Monitor → Revisit`; no new route without measured JTBD.
4. **Global data foundation:** economy × indicator × frequency × provider ×
   freshness × rights × verification matrix; async ingestion; provenance,
   vintage, revisions and release calendars.
5. **Production assurance:** provider contracts, semantic/revision/reconciliation
   checks, browser E2E, accessibility, performance, post-deploy smoke, queues,
   distributed cache/rate limits and independent release audit.
6. **Validated expansion:** advanced models only after evidence from waves 1–5;
   each experiment has a kill criterion and reversible scope.

## Five-epoch review

At epochs 5, 10, 15… pause feature selection. Review Product Goal alignment,
real user value, scope drift, independent reviewer integrity, provider/data/
runtime evidence, production readiness, approvals, rollback quality, scorecard
calibration and backlog health. Persist
`.ai-company/reports/process-review-epoch-NNNN.md`. Missing report blocks delivery.

## State machine

`PROPOSED → APPROVAL_PENDING → APPROVED → IMPLEMENTED → VERIFICATION_PENDING → AUDIT_PASSED → RELEASE_ELIGIBLE`.

Failure paths are `REVISE | ROLLBACK | HOLD | KILL`.

## CEO metrics

Use verified user value per epoch, core task success, time-to-first-evidence,
actual hydrated coverage, freshness SLA, reconciliation pass rate, p95 runtime,
P0/P1 regressions, independent rejection rate, rollback time, cost per verified
insight and Product Goal alignment ratio. Do not optimize lines of code, test
count or feature count.
