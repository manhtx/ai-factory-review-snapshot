The installed CLI sandbox utility reproduced private control reads under legacy read-only/workspace-write modes. Its supported named permission profile can deny filesystem root reads while reopening assigned workspace and minimal runtime paths. The first restrictive fixture failed because Node requires `/System/Library/OpenSSL`; a bounded read grant for that system directory allowed Node startup while control/auth fixtures stayed unreadable. Both outcomes are retained. [Official permissions documentation](https://learn.chatgpt.com/docs/permissions) states that legacy `--sandbox` settings override named profiles; do not combine them.

Plan: reuse existing sandbox module for explicit permission arguments; canonicalize control/workspace/dependency paths and reject unsafe overlap or unknown modes. The profile inherits workspace safeguards, denies broad root/temp access, permits workspace writes (or reads plus dispatcher-owned attempt temp/config paths for read-only roles), and grants dependency reads only. Replace Codex's legacy sandbox argument at the actual spawn call; a missing isolated workspace is refused before queue claim. No automatic fallback to the control checkout or broad mode.
