# Codex readable-root policy

Product lineage: Product Goal Authority/Trust/Traceable; standing local convergence authority. This is candidate source repair, not enrollment, migration or production activation.

The installed CLI sandbox utility reproduced private control reads under legacy read-only/workspace-write modes. Its supported named permission profile can deny filesystem root reads while reopening assigned workspace and minimal runtime paths. The first restrictive fixture failed because Node requires `/System/Library/OpenSSL`; a bounded read grant for that system directory allowed Node startup while control/auth fixtures stayed unreadable. Both outcomes are retained. [Official permissions documentation](https://learn.chatgpt.com/docs/permissions) states that legacy `--sandbox` settings override named profiles; do not combine them.

Plan: reuse existing sandbox module for explicit permission arguments; canonicalize control/workspace/dependency paths and reject unsafe overlap or unknown modes. The profile inherits workspace safeguards, denies broad root/temp access, permits workspace writes (or reads plus dispatcher-owned attempt temp/config paths for read-only roles), and grants dependency reads only. Replace Codex's legacy sandbox argument at the actual spawn call; a missing isolated workspace is refused before queue claim. No automatic fallback to the control checkout or broad mode. AGY's envelope and actual model tool invocation remain separate open prerequisites.

Affected modules: sandbox argument generator, dispatcher, CLI fixtures. CLI fixture mode remains on fixture files rather than environment. Adapt old standalone transport fixtures to explicit isolated workspace roots; provider stubs may observe trusted dispatcher state but are not model tool sandbox proof. Verify the generated arguments against the actual installed sandbox utility with dummy control/auth files and symlink escapes, legitimate workspace/temp writes and read-only dependency behavior. Preserve private-source, Git-history, non-worktree caller and real-provider compatibility debt; run appropriate regression/typecheck/lint and seal exact source.

The named profile is beta and version-sensitive. Requested flags are not enforcement proof. Project/managed config, additional tool surfaces, actual provider authentication and both-runner coverage must be verified before enrolling a gateway. No further ad-hoc SBPL exceptions are authorized by this change. A/B/C/D remain UNPROVEN.

Read-only model tools emit their final artifact/marker through stdout; the trusted CLI's existing `--output-last-message` records it at the assigned attempt artifact name. Product paths remain read-only; only dispatcher-created attempt temp/config paths are writable to tools. This requires verification of the real CLI output-file path, not only transport stubs. Existing non-worktree callers now receive an explicit preclaim refusal and remain a caller-migration debt; do not add unfenced Git operations to every read-only role as a shortcut while Git effect quiescence is open.

Initial implementation inherited a write rule from `:workspace` despite an absolute read rule. Actual utility testing caught it. The profile must override `:workspace_roots` with a scoped `.` rule. A quoted dotted CLI override also failed config parsing; the final serializer supplies one complete inline filesystem table with the scoped map. All initial failures are retained, not reclassified as PASS.
