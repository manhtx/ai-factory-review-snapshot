## Required invariants and implementation plan

1. Reuse the existing crash-released SQLite queue mutation gate in the existing macro-os resource root for cooperative acquisition and release. Its synchronous callback serializes the existing resource directory and metadata operations; it must not append or modify queue history. No new gate family, scheduler, state table or authority store.
2. Generate a unique resource lease identity and bind release to the originally issued identity and actual owner PID. A late release must preserve B byte-for-byte. A repeated release of an absent own lock may be an idempotent no-op; a different current owner must be rejected.
3. Never steal a live owner's admission because it is old. Recover only after valid owner metadata and an OS ESRCH observation prove that PID is absent. Permission errors, corrupt/missing metadata, symlinks, alias files, PID reuse or unknown liveness withhold admission without deleting state. An alive reused PID conservatively holds the old slot; this is not a process-start certificate.
4. Read quota evidence within acquisition exclusion. Only ENOENT means no pause. Present invalid/unreadable/aliased state returns UNKNOWN. A valid future pause holds; elapsed valid reset/backoff permits only the existing error-only reactive probe, never a claim that quota recovered. Preserve bounded backoff from the existing quota module when real detected_at/resume count facts exist.
5. Write private owner metadata durably before returning an admission handle. Crash before owner publication leaves unknown partial state and withholds automatic takeover; this requires explicit reconciliation. Crash after publication with a proven dead owner permits bounded serialized recovery. Resource effects followed by gate/durability failure must report COMMIT_UNCERTAIN rather than ordinary safe retry.

## Why this solution and change budget

Observed failure is stale resource ownership and unsafe recovery. A release identity check alone cannot serialize two dead-owner takeovers or protect the initialization window. Existing SQLite exclusion already provides process-death lock release and serialized callbacks. Reuse it instead of another lock/recovery protocol. Added primitives: none. Retired complexity: age-based stealing, unconditional release, ambiguous-state deletion. Added authority: none; release is narrowed to the original issuer. Queue state remains untouched. Resource directory/metadata are still filesystem state, not a global transaction with quota, queue, evidence or provider effects.
